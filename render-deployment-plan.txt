ISSUES ENCOUNTERED AND SOLUTIONS
================================

Issue 1: Login API Connectivity - "Failed to fetch"
==================================================

Problem:
- Frontend services (AuthService, ApiService) were hardcoded to localhost
- Production environment wasn't using correct API URL
- Angular build wasn't replacing environment files properly

Root Causes:
1. src/app/services/auth.service.ts - hardcoded localhost URL
2. src/app/services/api.ts - hardcoded localhost URL  
3. angular.json missing fileReplacements for production builds

Solutions Applied:
1. Updated AuthService to use environment variable:
   File: src/app/services/auth.service.ts (line 28)
   FROM: private baseUrl = 'http://localhost:3001/api/auth';
   TO:   private baseUrl = `${environment.api.baseUrl}/auth`;

2. Updated ApiService to use environment variable:
   File: src/app/services/api.ts 
   FROM: private baseUrl = 'http://localhost:3001/api';
   TO:   private baseUrl = environment.api.baseUrl;

3. Fixed Angular production build configuration:
   File: angular.json - Added fileReplacements under production config
   Added: "fileReplacements": [{"replace": "src/environments/environment.ts", "with": "src/environments/environment.prod.ts"}]

4. Verified production environment:
   File: src/environments/environment.prod.ts
   baseUrl: 'https://rfm-backend-7xts.onrender.com/api'

Issue 2: CORS Configuration Problems
====================================

Problem:
- Backend CORS wasn't allowing frontend domain
- Deployed backend was using old compiled version without CORS updates

Root Cause:
- backend/dist/server.js was outdated after CORS changes
- Manual rebuild was required before deployment

Solution Applied:
1. Updated CORS configuration in backend:
   File: backend/src/server.ts (lines 15-21)
   Added frontend Render URL to origins:
   origin: ['http://localhost:4200', 'http://localhost:3000', 'https://rfm-frontend-qnnw.onrender.com']

2. Manual rebuild and deployment:
   - Ran: npm run build in backend directory
   - Committed updated backend/dist/server.js
   - Manually redeployed backend on Render

Issue 3: SPA Routing - Direct URL Access Returns "Not Found"
============================================================

Problem:
- Accessing /login, /admin/dashboard directly showed "Not Found"
- Navigation via buttons worked fine
- This is classic SPA routing issue on static hosting

Diagnosis Process:
1. Verified Angular routing was configured correctly (app.routes.ts)
2. Checked app.config.ts router configuration
3. Confirmed _redirects file doesn't work on Render (Netlify format)
4. Tested render.yaml approach - not applicable to existing services

Failed Solutions Attempted:
1. Created public/_redirects file with "/* /index.html 200" - NOT supported by Render
2. Created render.yaml with rewrite rules - NOT applicable to existing services
3. Modified app.config.ts with router options - didn't solve server-side issue

Root Cause:
Render Static Sites need server-side configuration to handle SPA routing, not just client-side changes.

Final Solution:
Configured redirect rules directly in Render Dashboard:
- Go to rfm-frontend static site settings
- Navigate to "Redirects and Rewrites" section  
- Add rule: Source: /*, Destination: /index.html, Action: Rewrite
- This tells Render to serve index.html for all routes that don't match actual files

TROUBLESHOOTING GUIDE
====================

If login fails with "Failed to fetch":
1. Check backend health endpoint
2. Verify CORS configuration includes frontend URL
3. Confirm frontend environment.prod.ts has correct backend URL
4. Ensure backend/dist/server.js was rebuilt after changes

If direct URLs show "Not Found":
1. Verify Redirects/Rewrites rule in Render dashboard
2. Rule should be: /* -> /index.html (Rewrite, not Redirect)

If environment variables not working:
1. Check angular.json has fileReplacements configuration
2. Verify production build uses environment.prod.ts
3. Confirm all services import from environment file
