### 1. **TypeScript Interface Mismatch** ⚠️ CRITICAL

**Problem:** Frontend `ProductData` interface expects `image_url` but plan suggests adding `images` field

**Current Frontend Interface:**
```typescript
// src/app/services/api.ts
export interface ProductData {
  product_id?: number;
  product_name: string;
  category: string;
  base_price: number;
  description?: string | null;

  cloudinary_public_id?: string | null;
  status?: 'Active' | 'Inactive' | 'Archived';
  stock_quantity?: number;
  sku?: string | null;
  sizes?: string | string[] | null; // Can be JSON string or array
  tags?: string | string[] | null;  // Can be JSON string or array
  created_at?: string;
  updated_at?: string;
}
```

**Impact:** If we add `images` field but don't update TypeScript interface, frontend will have type errors!

**Solution:** Update `ProductData` interface:

### 2. **JSON Field Handling Inconsistency** ⚠️ HIGH RISK

**Problem:** Current code has inconsistent JSON handling

**Current Backend Code:**
```typescript
// catalog.routes.ts - Line 65-66
sizes: sizes ? JSON.stringify(sizes) : null,
tags: tags ? JSON.stringify(tags) : null

// Line 96-97
if (req.body.sizes) updateData.sizes = JSON.stringify(req.body.sizes);
if (req.body.tags) updateData.tags = JSON.stringify(req.body.tags);
```

**Frontend Interface:**
```typescript
sizes?: string | string[] | null; // Can be JSON string or array
tags?: string | string[] | null;  // Can be JSON string or array
```

**Issue:** Frontend can receive either stringified JSON OR array, but new fields will only be stringified!

**Solution:** Standardize JSON handling:
```typescript
// Backend: Always stringify JSON fields
colors: colors ? JSON.stringify(colors) : null,
images: images ? JSON.stringify(images) : null,
stock_by_size_color: stock_by_size_color ? JSON.stringify(stock_by_size_color) : null

// Frontend: Always expect stringified JSON, parse when needed
colors?: string | null;  // JSON string, not array!
images?: string | null;  // JSON string, not array!
```

### 7. **Migration Script Column Order** ⚠️ MEDIUM RISK

**Problem:** `AFTER` clause in ALTER TABLE might fail if column doesn't exist

**Current Plan:**
```sql
ADD COLUMN colors JSON DEFAULT NULL AFTER sizes,
ADD COLUMN stock_by_size_color JSON DEFAULT NULL AFTER stock_quantity,
```

**Issue:** If `sizes` or `stock_quantity` columns don't exist, migration fails!

**Solution:** Use safer column positioning:
```sql
ALTER TABLE catalog_clothing
  ADD COLUMN colors JSON DEFAULT NULL,
  ADD COLUMN stock_by_size_color JSON DEFAULT NULL,
  ADD COLUMN images JSON DEFAULT NULL,
  ADD COLUMN material VARCHAR(100),
  ADD COLUMN weight_grams INT,
  ADD COLUMN gender ENUM('Men', 'Women', 'Unisex', 'Kids') DEFAULT 'Unisex',
  ADD COLUMN fit_type VARCHAR(50),
  ADD COLUMN allows_customization BOOLEAN DEFAULT TRUE,
  ADD COLUMN customization_areas JSON DEFAULT NULL,
  ADD COLUMN max_print_size VARCHAR(50),
  ADD COLUMN production_days INT DEFAULT 3;
```
